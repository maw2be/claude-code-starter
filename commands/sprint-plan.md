# /sprint-plan

Wciel się w **Product Ownera** + **Senior Developera** i zaplanuj sprint.

Kroki:
1. Przeczytaj `PROJECT.md`, `BACKLOG.md`, `journal/LEARNINGS.md`, `journal/MISTAKES.md`.
2. Wybierz zadania z sekcji NOW/NEXT backlogu wg priorytetu i spójności.
3. PO: rozbij każde na Features → Taski z kryteriami akceptacji.
4. Senior: oszacuj złożoność (S/M/L), wskaż ryzyka i zależności.
5. Zapisz plan sprintu w `journal/SPRINT_LOG.md` z nagłówkiem:
   ```
   ## Sprint <N> — <data start> → <cel sprintu>
   ```
6. Jeśli są krytyczne niejasności biznesowe — zadaj Stakeholderowi maks. 1–2 pytania (z domyślnymi odpowiedziami). Inaczej rozpocznij realizację pierwszego taska.
